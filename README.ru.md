<p align="center">Плагин для Claude Code и других кодинг-агентов: передаёт чётко сформулированную задачу разработки локальному агенту <a href="https://zcode.z.ai">ZCode</a> (GLM), запускает её в изолированном git-рабочем дереве, пропускает каждую запись через механические жёсткие правила (остальное останавливается и ждёт человека), а результат предлагает принять по <code>git diff</code> и тестам — а не на слово агенту.</p>

## Почему

Claude Code силён в обдумывании задачи. ZCode дёшево и сердито выписывает код. Без присмотра любой из них уйдёт в сторону. Этот плагин расставляет всех по местам:

- **Файл задания — это контракт.** Claude пишет `tasks/T-xxx.md`; сообщение для ZCode — лишь дверной звонок.
- **Рабочее дерево — это песочница.** ZCode работает в `~/.zcode-executor/worktrees/<репозиторий>`, а не в вашем основном рабочем дереве.
- **Шлюз решает, кого спросить.** Каждый вызов инструмента ZCode проходит механические жёсткие правила (граница worktree, самозащита шлюза), а всё остальное останавливается и ждёт человека — вас или головного агента, действующего от вашего имени. Ничего не разрешается и не отклоняется за вас автоматически. *(облегчённый форк: конвейер модельной проверки и внепиковая очередь удалены, см. [LEAN-FORK.md](LEAN-FORK.md))*
- **Свидетельства важнее рассказов.** Принимайте работу по `git diff` и своим тестам.

## Быстрый старт

Вставьте это своему агенту (Claude Code, Codex или любому, у кого есть shell):

> `Read https://github.com/kyomio/zcode-executor/blob/main/README.md and install zcode-executor by following its Install section, then run zcode-executor doctor.`

## Как пользоваться

CLI вы сами не запускаете. Вы описываете задачу своему агенту, а он запускает skill: пишет файл задания, создаёт рабочее дерево, отправляет задание ZCode, ждёт, затем сверяет результат по `git diff` и вашим тестам и только потом сообщает, что готово. Если ZCode попросит то, что шлюз сам не пропустит, агент остановится и спросит вас.

Два способа запустить:

**Напрямую вызвать skill**

```
/zcode-executor добавь к команде status флаг --json, тесты должны остаться зелёными
```

(Полное имя — `/zcode-executor:zcode-executor`; короткая форма работает, пока имя не занял другой плагин.)

**Или просто сказать своими словами**

```
Поручи рефакторинг lib/queue.mjs zcode.
```

В любом случае опишите, как выглядит «готово»: какая команда должна проходить, какой файл должен существовать, какой вывод вы ждёте. Агент превратит это в критерии приёмки в файле задания, а файл задания — контракт; отправленное ZCode сообщение — только дверной звонок.

## Два слоя

- **Слой передачи работы** — отправка и приёмка: файл задания → изолированное рабочее дерево → локальный идентификатор сессии → фоновый runner → `git diff` и тесты. Об этом — команды CLI и skill.
- **Слой безопасности** — автоматическая обработка запросов разрешения от ZCode: фиксированный набор механических жёстких правил, которые никто не может обойти (записи вне worktree, касание собственных данных инструмента), затем человек для всего остального. Шлюз умеет *спрашивать*; отказывать или разрешать за вас он не может.

### Требования

- macOS или Linux. **Windows пока не поддерживается.** Бандл приложения ZCode ищется там, куда его кладёт каждая платформа (`/Applications/…`, `/opt/ZCode/…`, `/usr/share/zcode/…`); если он установлен в другое место, направьте `ZCODE_BIN` на `zcode.cjs`.
- Node ≥ 22 (app-server ZCode требует `node:sqlite`).
- Установленное и залогиненное десктоп-приложение ZCode **≥ 3.12.2** (3.11 и старше не поддерживаются). Работают оба способа входа: аккаунтный (OAuth) Coding Plan — CLI расшифровывает платформенный ключ, который приложение хранит в `~/.zcode/v2/credentials.json` (персональные и командные планы; читаются только четыре нужных ключа, плюс `zcodejwttoken` для start-plan-отправок) — или провайдер с API-ключом в `~/.zcode/v2/config.json`. Оба файла только читаются; ничего не записывается обратно.

## Рекомендуемый процесс

Так был собран сам zcode-executor:

1. **Планируйте с Claude Fable.** Самая сильная модель на рассуждения выпытывает подробности, пишет спецификацию и превращает её в файлы заданий с машинно-проверяемыми критериями приёмки.
2. **Исполняйте с ZCode.** Каждое задание уходит в сессию GLM в своём рабочем дереве через `zcode-executor`; шлюз разрешений обрабатывает рутинные подтверждения.
3. **Fable делает грубый проход, Opus — ревью.** Fable проверяет `git diff` и гоняет тесты; если всё сходится, он отправляет субагента Opus на построчное ревью кода. Находки возвращаются в ту же сессию ZCode следующим файлом задания.
4. **Сливайте по свидетельствам.** Ничего не попадает в основную ветку, пока тесты и ревью не пройдены.

Такое разделение держит дорогую модель на вынесении суждений, а дешёвую — на наборе текста.

## Команды

| Команда | Что делает |
| --- | --- |
| `doctor [--json]` | Самопроверка без траты квоты: находит `zcode.cjs` и комплектный `zcode-builtin.json` (ZCode App ≥ 3.12.2), сообщает оба источника провайдеров, делает один настоящий handshake, показывает уровни моделей |
| `models [--json]` | Список доступных моделей с уровнями размышления и назначением уровней |
| `new --cwd <abs> [--title T] [--tier fast\|strong] [--thought L] [--deny "Tool…"] [--provider id] [--json]` | Регистрирует сессию (возвращает локальный идентификатор `x_…`); сессия ZCode создаётся при первом `send` |
| `send <id> <text\|-> [--task file] [--wait] [--timeout s] [--steer] [--stream] [--json]` | Ставит сообщение в очередь; `--wait` следует за ходом до завершения или блокировки; `--task` — файл задания, который проверка считает вашей авторизацией; `--steer` вмешивается в идущий ход — срабатывает на границе следующего инструмента, а если границ нет, после конца хода |
| `follow <id> [--timeout s] [--stream] [--json]` | Следует за фоновым runner до результата или ожидающего запроса |
| `status <id> [--tools N] [--json]` | Снимок только для чтения: фаза, недавние инструменты (с командой или путём), очередь, ожидания, последний результат |
| `list [--project kw] [--json]` | Зарегистрированные сессии с фазой, уровнем и последним исходом; `--json` добавляет репозиторий-владелец |
| `cancel <id>` | Отклоняет любой ожидающий запрос, останавливает ход, очищает очередь |
| `approve <id>` / `deny <id>` | Отвечает на ожидающий запрос разрешения (разрешение — только `allow_once`) |
| `answer <id> [--] <values…>` | Отвечает на ожидающий вопрос по индексу, значению или метке; мультиселект — через запятую |

Коды выхода: `0` готово · `1` неверный вызов / не удаётся запуститься · `2` отказ (белый список, неизвестная сессия, плохой уровень) · `3` истёк таймаут `--wait` (ход отменён) · `4` ход провалился / отменён · `5` **блокировка, ждёт человека** (запрос разрешения или вопрос).

## Конфигурация

`~/.zcode-executor/config.json` (каталог переопределяется переменной `ZCODE_EXECUTOR_HOME`). Все поля необязательны.

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| `allowedRoots` | `["~/.zcode-executor/worktrees"]` | Каталоги, куда может указывать `new --cwd` (симлинки раскрываются) |
| `waitTimeoutSec` | `3600` | Таймаут `send --wait`; по его истечении ход останавливается |
| `preferredProvider` | аккаунтный персональный план › аккаунтный командный план › `config.json` coding plan | Какого провайдера выбирать, когда одна и та же модель есть у нескольких, например `account:bigmodel-team-coding-plan` |
| `tiers` | автоматически по имени | Переопределение того, какая модель `fast` / `strong` |

## Модель безопасности

- **Жёсткие правила** — константы кода, а не конфигурация: любой инструмент с путём, пишущий вне рабочего дерева, останавливается и ждёт человека. Таблица правил повторяет категории auto mode Claude Code (учётные данные, эксфильтрация, разрушительный git, удаление, supply chain, закрепление, деплои, общие ресурсы, внешние записи).
- **Шлюз никогда не отказывает.** Его единственный исход — *спросить*: попадание в жёсткое правило несёт id правила, всё остальное объясняет, почему остановилось. Разрешить или отказать — всегда решение человека (или головного агента).
- **Разрешать можно только разрешённое.** `approve` требует наличия варианта `allow_once`; «всегда разрешать» нет, автосогласования нет.
- **Секреты жёстко ограничены.** Ключ провайдера ZCode уходит только в путь app-server; известные значения секретов вычищаются из `pending.json`, событий и логов перед записью.
- **Ответы привязаны к запросам.** Каждый `approve`/`deny`/`answer` несёт id запроса; устаревшие ответы выбрасываются.
- **Шлюз защищает себя.** Всё, что трогает собственный каталог данных zcode-executor (кроме стандартного корня `worktrees/` и рабочего дерева текущей сессии) или вызывает CLI `zcode-executor`, останавливается и ждёт человека. Исполнитель работает под тем же пользователем ОС, что и runner, поэтому правило ловит только прямые написания: склейка переменных или скрипт, записанный и запущенный позже, не распознаются и остаются на совести человека.
- **Основание согласования заморожено в момент отправки.** Файл задания снимается при постановке хода в очередь; правка файла задания после этого не может изменить то, с чем ответ на подвеску можно сверить как «сказанным пользователем».
- **Учётные данные хост-агента не пробрасываются вниз.** `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `GITHUB_TOKEN`, `GH_TOKEN` и подобные переменные вырезаются при запуске ZCode; добавляйте `--deny "WebFetch WebSearch"`, когда заданию не нужен доступ в сеть. Это убирает эти два инструмента; Bash, js и MCP-инструменты всё ещё могут ходить в сеть.

## Разработка

```bash
npm test          # 414 случаев на скриптовом моке app-server плюс проверка дрейфа версий документации; токены не тратятся
node --check lib/**/*.mjs
```

Релизы управляются тегами: `npm version patch` поднимает `package.json`, синхронизирует версию во все три README и манифесты плагинов всех хостов, создаёт коммит и тег; `git push --follow-tags` запускает workflow, который гоняет тесты, публикует в npm (Trusted Publishing, без токена) и создаёт GitHub Release. ## Вопросы и ответы

**Работает ли это с агентами, кроме ZCode?** Нет, так задумано. Исполнитель — только ZCode; планирующей стороной может быть Claude Code, Codex и любой агент, умеющий запускать shell.

**Почему бы просто не дать Claude править код?** Стоимость и изоляция. GLM coding plan ZCode тарифицируется по кредитам и намного дешевле токенов фронтальных моделей (внутри ZCode биллинг идёт по 67% от списка), а рабочее дерево не даёт двум агентам править одни и те же файлы.

**Сколько стоит задание?** В токенах: изменение одного файла — это примерно 30–65k ввода на стороне ZCode (его системный промпт тяжёлый). В пересчёте на кредиты coding plan по льготной ставке ZCode это малая доля от стоимости той же правки фронтальной моделью.

**Куда делись проверка моделью и внепиковые отправки?** Это облегчённый форк: шлюз чисто механический (жёсткие правила, затем человек), отправка всегда обычная. См. [LEAN-FORK.md](LEAN-FORK.md).
