<p align="center">Плагин для Claude Code и других кодинг-агентов: передаёт чётко сформулированную задачу разработки локальному агенту <a href="https://zcode.z.ai">ZCode</a> (GLM), запускает её в изолированном git-рабочем дереве, пропускает каждую запись через жёсткие правила и проверку моделью, а результат предлагает принять по <code>git diff</code> и тестам — а не на слово агенту.</p>

## Почему

Claude Code силён в обдумывании задачи. ZCode дёшево и сердито выписывает код. Без присмотра любой из них уйдёт в сторону. Этот плагин расставляет всех по местам:

- **Файл задания — это контракт.** Claude пишет `tasks/T-xxx.md`; сообщение для ZCode — лишь дверной звонок.
- **Рабочее дерево — это песочница.** ZCode работает в `~/.zcode-executor/worktrees/<репозиторий>`, а не в вашем основном рабочем дереве.
- **Шлюз решает, кого спросить.** Каждый вызов инструмента ZCode проходит жёсткие правила, проверку моделью и, если нужно, человека. Необязательная предварительная проверка Jev может разрешить заранее; иначе работает исходная быстрая проверка ZCode `fast` + `low`, за которой при необходимости следует углублённая проверка. Модели могут только *разрешить* или *спросить*; отказывать за вас они не вправе.
- **Свидетельства важнее рассказов.** Принимайте работу по `git diff` и своим тестам.

## Быстрый старт

Вставьте это своему агенту (Claude Code, Codex или любому, у кого есть shell):

> `Read https://github.com/kyomio/zcode-executor/blob/main/README.md and install zcode-executor by following its Install section, then run zcode-executor doctor.`

## Как пользоваться

CLI вы сами не запускаете. Вы описываете задачу своему агенту, а он запускает skill: пишет файл задания, создаёт рабочее дерево, отправляет задание ZCode, ждёт, затем сверяет результат по `git diff` и вашим тестам и только потом сообщает, что готово. Если ZCode попросит то, что шлюз сам не пропустит, агент остановится и спросит вас.

Два способа запустить:

**Напрямую вызвать skill**

```
/zcode-executor добавь к команде status флаг --json, тесты должны остаться зелёными
```

(Полное имя — `/zcode-executor:zcode-executor`; короткая форма работает, пока имя не занял другой плагин.)

**Или просто сказать своими словами**

```
Поручи рефакторинг lib/queue.mjs zcode.
```

В любом случае опишите, как выглядит «готово»: какая команда должна проходить, какой файл должен существовать, какой вывод вы ждёте. Агент превратит это в критерии приёмки в файле задания, а файл задания — контракт; отправленное ZCode сообщение — только дверной звонок.

## Два слоя

- **Слой передачи работы** — отправка и приёмка: файл задания → изолированное рабочее дерево → локальный идентификатор сессии → фоновый runner → `git diff` и тесты. Об этом — команды CLI и skill.
- **Слой безопасности** — автоматическая обработка запросов разрешения от ZCode. Логика повторяет *auto mode* Claude Code: фиксированная таблица жёстких правил, которые никто не может обойти, затем **необязательная предварительная проверка Jev → быстрая проверка ZCode → при необходимости углублённая проверка**, затем человек, если проверка не разрешила. Jev добавляет путь раннего разрешения; он не заменяет быструю проверку ZCode. Проверяющие могут *разрешить* или *спросить*; отказать за вас они не могут.

## Установка

### Claude Code (маркетплейс плагинов)

Этот репозиторий — одновременно плагин и его собственный маркетплейс.

```bash
claude plugin marketplace add kyomio/zcode-executor      # или локальный путь
claude plugin install zcode-executor@zcode-executor --scope user
```

Пока плагин включён, `bin/zcode-executor` добавляется в `PATH` для Bash; skill появляется как `/zcode-executor:zcode-executor`. Фраза «поручи это zcode» запускает его.

Плагин также несёт **мод для Claude Code** (модуль функциональных хуков, `hooks/`): введите `/zcode`, чтобы открыть [панель наблюдения](#панель-наблюдения) — живой обзор сессий zcode этого проекта. Она открывается и сама, когда Claude отправляет задачу, и добавляет сводку в строку состояния и всплывающие уведомления. Настраивать ничего не нужно; нужна версия Claude Code с модами на функциональных хуках (API в раннем доступе).

### DeepSeek Harness (DSH)

npm-пакет **и есть** DSH-плагин: корневой `package.json` несёт определение `dsh` (бандл `cordis.patch.yml` + клиент правой боковой панели), а код плагина — собранный вывод в `dsh-plugin/lib/` (исходники в [dsh-plugin/](dsh-plugin/README.md)). На странице плагинов десктоп-приложения DSH достаточно установки по имени npm-пакета `zcode-executor` — приложение само зарегистрирует бандл; ни ручного `link:`, ни правки конфига. Плагин обучает DSH-агента полному циклу передачи работы (skill симлинкуется в `~/.dsh/skills/` автоматически) и добавляет вкладку **«zcode 任务» (задачи zcode)** в официальную правую боковую панель — та же живая панель наблюдения, обновляется примерно раз в секунду при нулевой квоте. Локальная разработка: `pnpm install && npm run build` внутри `dsh-plugin/`, затем перезапустите десктоп-приложение.

### Kimi Work

В корне репозитория лежит нативный `kimi.plugin.json` (только skills; описанный выше мод для Claude Code — только для Claude и сюда не входит). Зарегистрируйте его в персональном маркете один раз, затем установите со вкладки «个人» (персональная):

```bash
kimi-daimon kimi-plugin register-personal /path/to/zcode-executor
```

Как и агенты ниже, Kimi Work не добавляет `bin/` плагина в `PATH` — skill возвращается к `bin/zcode-executor` относительно корня плагина или к `npx zcode-executor`. Фразы 「让 zcode 去做」「派给 zcode」 («поручи zcode») запускают skill.

### Требования

- macOS или Linux. **Windows пока не поддерживается.** Бандл приложения ZCode ищется там, куда его кладёт каждая платформа (`/Applications/…`, `/opt/ZCode/…`, `/usr/share/zcode/…`); если он установлен в другое место, направьте `ZCODE_BIN` на `zcode.cjs`.
- Node ≥ 22 (app-server ZCode требует `node:sqlite`).
- Установленное и залогиненное десктоп-приложение ZCode **≥ 3.12.2** (3.11 и старше не поддерживаются). Работают оба способа входа: аккаунтный (OAuth) Coding Plan — CLI расшифровывает платформенный ключ, который приложение хранит в `~/.zcode/v2/credentials.json` (персональные и командные планы; читаются только четыре нужных ключа, плюс `zcodejwttoken` для внепиковых отправок) — или провайдер с API-ключом в `~/.zcode/v2/config.json`. Оба файла только читаются; ничего не записывается обратно.

## Рекомендуемый процесс

Так был собран сам zcode-executor:

1. **Планируйте с Claude Fable.** Самая сильная модель на рассуждения выпытывает подробности, пишет спецификацию и превращает её в файлы заданий с машинно-проверяемыми критериями приёмки.
2. **Исполняйте с ZCode.** Каждое задание уходит в сессию GLM в своём рабочем дереве через `zcode-executor`; шлюз разрешений обрабатывает рутинные подтверждения.
3. **Fable делает грубый проход, Opus — ревью.** Fable проверяет `git diff` и гоняет тесты; если всё сходится, он отправляет субагента Opus на построчное ревью кода. Находки возвращаются в ту же сессию ZCode следующим файлом задания.
4. **Сливайте по свидетельствам.** Ничего не попадает в основную ветку, пока тесты и ревью не пройдены.

Такое разделение держит дорогую модель на вынесении суждений, а дешёвую — на наборе текста.

## Панель наблюдения

Панель есть не только в Claude Code: плагин Claude Code и DSH-плагин несут по своей, и обе питаются одним потоком `watch --json`.

**Claude Code** (терминал или вкладка Code в десктопе): введите `/zcode`, чтобы открыть живую панель, показывающую, чем заняты сессии zcode этого проекта:

- **Ждут вас**: ожидающие запросы разрешения (полная команда и причина), вопросы, погибшие runner'ы;
- **Выполняются**: последнее сообщение исполнителя, отрисованное как Markdown, запускаемый инструмент с его аргументами, недавно завершённые инструменты (ошибки — красным) и позиция в очереди для внепиковых отправок;
- **Завершённые**: сессии, закончившиеся за последние 10 минут, показывают исход и последнее сообщение; более старые — по одной строке.

Сообщение длиннее двух строк сворачивается до первых двух; нажмите **Expand reply**, чтобы прочитать целиком, и **Collapse**, чтобы свернуть снова.

Панель открывается сама, когда Claude отправляет задачу. Строка состояния суммирует идущие ходы и ожидающие запросы, а всплывашка появляется при новом ожидающем запросе, завершённом ходе или погибшем runner. Панель только читает: ожидающие запросы всё равно идут через Claude.
Она читает `zcode-executor watch --json` (только чтение, долгоживущий процесс, без квоты) и показывает только сессии того репозитория, в котором находится сессия Claude. Если панель сообщает, что node не найден, задайте `nodePath` в настройках плагина.

**DSH**: описанная выше установка `dsh-plugin/` показывает тот же живой обзор во вкладке «zcode 任务» правой боковой панели, обновление примерно раз в секунду при нулевой квоте. Там панель тоже только читает — ожидающие запросы уходят агенту-отправителю, который обрабатывает их по правилам ответов из skill.

У остальных агентов панели нет — они продолжают пользоваться skill и CLI.

## Команды

| Команда | Что делает |
| --- | --- |
| `doctor [--offpeak] [--json]` | Самопроверка без траты квоты: находит `zcode.cjs` и комплектный `zcode-builtin.json` (ZCode App ≥ 3.12.2), сообщает оба источника провайдеров, делает один настоящий handshake, показывает уровни моделей и конвейер проверки у только что запущенного runner (Jev не вызывает) и проверяет внепиковый интерфейс — этот шаг выходит в сеть и оставляет одну самопроверочную сессию в собственном хранилище сессий zcode. `--offpeak` выполняет только этот шаг |
| `quota [--json]` | Сколько внепиковых талонов инструмент взял сегодня и выдал бы сервер талон прямо сейчас; квота не тратится, app-server не запускается |
| `models [--json]` | Список доступных моделей с уровнями размышления и назначением уровней |
| `new --cwd <abs> [--title T] [--tier fast\|strong] [--thought L] [--deny "Tool…"] [--provider id] [--json]` | Регистрирует сессию (возвращает локальный идентификатор `x_…`); сессия ZCode создаётся при первом `send` |
| `send <id> <text\|-> [--task file] [--wait] [--timeout s] [--steer] [--stream] [--json]` | Ставит сообщение в очередь; `--wait` следует за ходом до завершения или блокировки; `--task` — файл задания, который проверка считает вашей авторизацией; `--steer` вмешивается в идущий ход — срабатывает на границе следующего инструмента, а если границ нет, после конца хода |
| `send <id> <text\|-> --offpeak [--task file] [--wait] [--timeout s] [--stream] [--json]` | Внепиковая отправка: берёт талон на месте и запускает ход на бесплатной внепиковой ёмкости Coding Plan, когда талон готов (см. ниже) |
| `send <id> --offpeak --resume [--wait] [--stream] [--json]` | Перезапускает runner для внепиковой отправки, оставшейся незавершённой после выхода хода или гибели runner |
| `follow <id> [--timeout s] [--stream] [--json]` | Следует за фоновым runner до результата или ожидающего запроса |
| `status <id> [--tools N] [--json]` | Снимок только для чтения: фаза, недавние инструменты (с командой или путём), очередь, ожидания, последний результат |
| `list [--project kw] [--json]` | Зарегистрированные сессии с фазой, уровнем и последним исходом; `--json` добавляет репозиторий-владелец |
| `watch [--json]` | Только чтение, долгоживущий: печатает снимок сессии при каждом изменении; питает панель наблюдения |
| `cancel <id>` | Отклоняет любой ожидающий запрос, останавливает ход, очищает очередь |
| `approve <id>` / `deny <id>` | Отвечает на ожидающий запрос разрешения (разрешение — только `allow_once`) |
| `answer <id> [--] <values…>` | Отвечает на ожидающий вопрос по индексу, значению или метке; мультиселект — через запятую |

Коды выхода: `0` готово · `1` неверный вызов / не удаётся запуститься · `2` отказ (белый список, неизвестная сессия, плохой уровень; внепиковая отправка отклонена до или во время взятия талона) · `3` истёк таймаут `--wait` (ход отменён) · `4` ход провалился / отменён · `5` **блокировка, ждёт человека** (запрос разрешения или вопрос).

### Внепиковые отправки

Внепиковая отправка запускает ход на бесплатной внепиковой ёмкости подписки Coding Plan вместо квоты вашего плана. Когда она стартует, решает сервер: `send --offpeak` берёт талон и встаёт в очередь, а ход запускается, когда талон готов. Приёмка та же, что у обычной отправки. Требования: аккаунтный вход на персональный Coding Plan в приложении ZCode и модель сессии из списка внепиковых моделей. Сессия должна простаивать; пока внепиковая отправка стоит в очереди или выполняется, обычные отправки в эту сессию отклоняются — заведите для внепиковой работы отдельную сессию. Просроченные талоны перевыпускаются автоматически (до трёх талонов на отправку), `cancel` закрывает талон на любом этапе, а `quota` показывает расход за сегодня (наблюдалось около трёх талонов в день). Обычные отправки остаются по умолчанию; skill сообщит, когда внепиковая отправка доступна, и переключится только по вашей просьбе.

## Конфигурация

`~/.zcode-executor/config.json` (каталог переопределяется переменной `ZCODE_EXECUTOR_HOME`). Все поля необязательны.

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| `allowedRoots` | `["~/.zcode-executor/worktrees"]` | Каталоги, куда может указывать `new --cwd` (симлинки раскрываются) |
| `waitTimeoutSec` | `3600` | Таймаут `send --wait`; по его истечении ход останавливается |
| `preferredProvider` | аккаунтный персональный план › аккаунтный командный план › `config.json` coding plan | Какого провайдера выбирать, когда одна и та же модель есть у нескольких, например `account:bigmodel-team-coding-plan` |
| `tiers` | автоматически по имени | Переопределение того, какая модель `fast` / `strong` |
| `review` | `{enabled, model, thought:"low", fastMaxTokens:300, slowMaxTokens:2000, timeoutMs:60000}` | Проверка моделью: вкл/выкл, модель ZCode (по умолчанию — уровень `fast`), уровень размышления, бюджеты токенов, таймаут вызова |
| `review.jev.apiKey` | отсутствует | Непустой ключ включает предварительную проверку Jev перед быстрой проверкой ZCode + `review.thought` (по умолчанию `low`); отсутствие или одни пробелы оставляют исходную цепочку ZCode |
| `review.jev.proxy` | отсутствует | Необязательный URL прокси `http(s)://` (допускается userinfo, уходит как Basic `Proxy-Authorization`). HTTPS-запросы Jev идут через CONNECT-туннель этого прокси. Игнорируется, если `review.jev.apiKey` отсутствует |
| `review.jev.model` | `jev-latest` | Необязательный ID или псевдоним модели Jev. Порог срабатывания и схема настраивались на `jev-1.13.0`; фиксация версии возвращает прежнее поведение |
| `environment` / `sensitive` | `[]` | Дополнительные факты и чувствительные места, показываемые проверочным вызовам ZCode (в Jev не уходят) |

### Опционально: включить предварительную проверку Jev

[Jev](https://docs.typesafe.ai/introduction) — структурированная модель решений от TypeSafe: она возвращает вероятности, а не объяснения. Она **не исполняет задания и не заменяет исходную быструю проверку ZCode**. Она лишь пытается разрешить действия заранее, когда свидетельств достаточно:

```text
После жёстких правил и проверок allow_once
  → предварительная проверка Jev: раннее разрешение, иначе продолжаем
  → быстрая проверка ZCode (по умолчанию fast + low): разрешено, иначе продолжаем
  → углублённая проверка ZCode: разрешить или спросить человека
```

- Пять проверок риска покрывают конфликты с границами задания, записи вне рабочего пространства, утечку учётных данных или эксфильтрацию чувствительных данных, разрушительные/внешние побочные эффекты и посторонние действия. Модель по умолчанию — псевдоним `jev-latest` (настраивается через `review.jev.model`); для раннего разрешения все пять вероятностей должны быть не выше `0.20`. Это порог срабатывания, а не гарантия безопасности.
- Тела Write/Edit/MultiEdit в Jev не уходят; эти действия сейчас пропускают предварительную проверку локально. Отсутствие намерения, усечённый обязательный ввод или учётные данные, которые нельзя надёжно вычистить, тоже дают локальный пропуск, **без HTTP-запроса к Jev**. Сама по себе сложность команды не является поводом для пропуска.
- Срабатывание Jev, таймауты, сетевые ошибки и невалидные ответы уходят в исходную быструю проверку ZCode — а не сразу в отказ или обязательную углублённую проверку. Провалившийся вызов быстрой проверки ZCode всё равно спрашивает человека.
- Ранние разрешения экономят последующие проверочные вызовы; остальные запросы добавляют последовательную задержку. У Jev сейчас общий бюджет 10 секунд, отдельный от `review.timeoutMs` ZCode. Фактическая выгода по скорости и стоимости зависит от доли ранних пропусков.

#### 1. Задайте API-ключ

Получите собственный ключ у [TypeSafe](https://typesafe.ai/) (см. [официальный быстрый старт](https://docs.typesafe.ai/introduction/quickstart)). Он отдельен от ключа провайдера ZCode; не редактируйте ради этого конфигурацию приложения ZCode.

Отредактируйте `~/.zcode-executor/config.json`. **Влейте поле `review.jev` в существующую конфигурацию; сохраните allowedRoots, настройки провайдеров и прочие поля, а не заменяйте файл целиком.** Если задан `ZCODE_EXECUTOR_HOME`, правьте `config.json` в том каталоге.

Никогда не кладите настоящий ключ в аргумент команды, переменную окружения shell, пример в репозитории, issue или лог. Значение ниже — только плейсхолдер; настоящий ключ не обязан иметь такой префикс:

```json
{
  "review": {
    "jev": {
      "apiKey": "jev_REPLACE_WITH_YOUR_KEY"
    }
  }
}
```

Опционально: если запросы Jev должны идти через прокси (например, endpoint недостижим напрямую), добавьте `proxy` в тот же объект `review.jev`. Принимается URL прокси `http://` или `https://` с поддержкой учётных данных `user:pass@`. Используется только HTTPS-вызовами Jev — цепочка отправки ZCode и трафик app-server не затрагиваются. `socks5://` не поддерживается:

```json
{
  "review": {
    "jev": {
      "apiKey": "jev_REPLACE_WITH_YOUR_KEY",
      "proxy": "http://127.0.0.1:7890"
    }
  }
}
```

#### 2. Защитите файл конфигурации

Файл должен уже существовать. Ограничьте его права (скорректируйте путь, если используете собственный каталог конфигурации):

```bash
chmod 600 ~/.zcode-executor/config.json
```

Когда задан `review.jev.apiKey`, `config.json` должен быть обычным файлом (не симлинком), принадлежащим текущему UID и доступным только этому владельцу (`0600` или строже). Иначе zcode-executor откажется его загружать. Переменной-запаски в окружении нет, отдельного режима или теневой настройки Jev нет. Уберите `apiKey` (или оставьте одни пробелы), чтобы работать только на исходной цепочке проверки ZCode. Установка `review.enabled` в `false` отключает **всю** проверку моделью, включая Jev; жёсткие правила продолжают действовать, остальные запросы разрешения ждут человека.

#### 3. Проверьте конфигурацию и активацию

```bash
zcode-executor doctor --json
```

При включённой проверке и настроенном ключе в выводе будет:

```json
"review": {
  "enabled": true,
  "fastScreen": "jev",
  "jevConfigured": true,
  "pipeline": ["jev", "zcode-fast", "zcode-slow"]
}
```

`doctor` не вызывает Jev. Он подтверждает конфигурацию и выбранную цепочку, **а не валидность ключа TypeSafe, остаток счёта или сетевую связность**. Этот фрагмент — часть полного JSON-ответа; `fastScreen` — поле совместимости, а не признак того, что быстрая проверка ZCode заменена.

Конфигурацию читают только заново запущенные runner; существующие не перечитывают её на лету. Дайте текущему runner завершиться перед следующей отправкой, чтобы изменения подхватились. Фактические согласования записывают `pass / flag / error / skip` и отфильтрованную диагностику в `executor.gate.preScreen`, никогда — ключ или полное состояние Jev.

**Чтобы отключить только Jev:** удалите `review.jev.apiKey`, оставив исходную цепочку быстрой и углублённой проверки ZCode. Не используйте для этого `review.enabled:false` — он отключает всю проверку моделью.

## Модель безопасности

- **Жёсткие правила** — константы кода, а не конфигурация: любой инструмент с путём, пишущий вне рабочего дерева, останавливается и ждёт человека. Таблица правил повторяет категории auto mode Claude Code (учётные данные, эксфильтрация, разрушительный git, удаление, supply chain, закрепление, деплои, общие ресурсы, внешние записи).
- **Проверяющие никогда не отказывают.** Их единственные финальные исходы — *разрешить* и *спросить*. Срабатывание/ошибка/пропуск Jev возвращаются в быструю проверку ZCode, затем при необходимости — углублённая. Провалившийся быстрый вызов ZCode всё равно спрашивает человека.
- **Разрешать можно только разрешённое.** Автосогласование и `approve` требуют наличия варианта `allow_once`; «всегда разрешать» нет.
- **Секреты жёстко ограничены.** Ключ провайдера ZCode по-прежнему уходит только в путь app-server. Необязательный ключ Jev — единственный намеренно постоянный секрет: живёт только в защищённом владельцем `config.json`, уходит только как авторизация Jev и никогда не копируется в события, ожидающее состояние, логи runner или процесс app-server.
- **Ответы привязаны к запросам.** Каждый `approve`/`deny`/`answer` несёт id запроса; устаревшие ответы выбрасываются.
- **Шлюз защищает себя.** Всё, что трогает собственный каталог данных zcode-executor (кроме стандартного корня `worktrees/` и рабочего дерева текущей сессии) или вызывает CLI `zcode-executor`, останавливается и ждёт человека. Исполнитель работает под тем же пользователем ОС, что и runner, поэтому правило ловит только прямые написания: склейка переменных или скрипт, записанный и запущенный позже, не распознаются и остаются на совести проверки моделью и человека.
- **Основание согласования заморожено в момент отправки.** Файл задания снимается при постановке хода в очередь, и проверка моделью читает только снимок; правка файла задания после этого не может изменить то, что проверка считает «сказанным пользователем».
- **Учётные данные хост-агента не пробрасываются вниз.** `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `GITHUB_TOKEN`, `GH_TOKEN` и подобные переменные вырезаются при запуске ZCode; добавляйте `--deny "WebFetch WebSearch"`, когда заданию не нужен доступ в сеть. Это убирает эти два инструмента; Bash, js и MCP-инструменты всё ещё могут ходить в сеть.

## Вопросы и ответы

**Работает ли это с агентами, кроме ZCode?** Нет, так задумано. Исполнитель — только ZCode; планирующей стороной может быть Claude Code, Codex и любой агент, умеющий запускать shell.

**Почему бы просто не дать Claude править код?** Стоимость и изоляция. GLM coding plan ZCode тарифицируется по кредитам и намного дешевле токенов фронтальных моделей (внутри ZCode биллинг идёт по 67% от списка, сверху — бесплатная внепиковая квота), а рабочее дерево не даёт двум агентам править одни и те же файлы.

**Сколько стоит задание?** В токенах: изменение одного файла — это примерно 30–65k ввода на стороне ZCode (его системный промпт тяжёлый); проверка добавляет около 5k ввода и 2 секунды на каждую быструю проверку. В пересчёте на кредиты coding plan по льготной ставке ZCode это малая доля от стоимости той же правки фронтальной моделью.

**Что если Jev не может решить?** Срабатывание, таймаут, ошибка или невалидный ответ возвращаются в исходную быструю проверку ZCode. Непропускающий или неразбираемый быстрый результат уходит в углублённую проверку; провалившийся быстрый вызов спрашивает вас напрямую (код выхода 5).

Jev пропускается локально, без HTTP-запроса, когда тела действий опущены, намерение отсутствует или обязательный ввод усечён. Сама по себе сложность команды — не повод для пропуска или отказа.

`doctor --json` сообщает `review.pipeline`: `['jev','zcode-fast','zcode-slow']` с ключом, последние два — без него, `[]` при выключенной проверке и `null` при ошибке конфигурации. Устаревшее поле `fastScreen` не означает, что Jev заменяет ZCode.
