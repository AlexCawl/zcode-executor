# zcode-executor

[English](CONTEXT.md) · [中文](CONTEXT.zh-CN.md) · Русский

Claude выступает прорабом: передаёт чётко сформулированную задачу локальному ZCode и принимает результат по объективным свидетельствам.
Этот файл определяет термины, а не реализацию; решения по реализации находятся в [decisions.md](decisions.ru.md) и [SPEC.md](SPEC.ru.md).

## Терминология

### Передача работы

**Сессия (session)**:
Диалог на стороне ZCode, обозначенный идентификатором `sess_`. Проект присваивает ему в реестре локальный идентификатор поручения с префиксом `x_`; CLI использует только локальный идентификатор.
Идентификатор ZCode `sess_` появляется только после первого хода.
_Не использовать_: run, экземпляр задачи, job

**Локальный идентификатор (local id)**:
Ключ сессии в реестре: `x_` и 8 шестнадцатеричных цифр. Во всех командах `<id>` обозначает именно его; `sess_` ZCode показывается рядом только в `list` и `--json` для сопоставления.
_Не использовать_: run id, идентификатор задачи

**Файл задания (task file)**:
Файл с договорённостями, который Claude пишет для исполнителя: цель, изменяемые файлы, критерии приёмки и запрещённые области.
_Не использовать_: подсказка, prompt, сообщение

**Снимок задания (task snapshot)**:
Содержимое файла задания в момент постановки отправки в очередь; хранится в каталоге данных (`runs/<id>/tasks/`). Проверка моделью читает намерение только из этого снимка, а не из исходного файла в рабочем дереве, который исполнитель может изменить.
_Не использовать_: резервная копия задания, кеш

**Отправка (send)**:
Передача одного сообщения в сессию, запускающая ход. Сообщение служит только сигналом; содержание находится в файле задания.
_Не использовать_: подача, prompt

**Ход (turn)**:
Вся работа исполнителя с момента получения отправки до остановки.
_Не использовать_: раунд, prompt, run

**Приёмка (acceptance)**:
Claude определяет завершённость задания по `git diff` и результатам тестов. Рассказ исполнителя доказательством не считается.
_Не использовать_: подтверждение, review

**Отправка во внепиковое время (off-peak send)**:
Отправка, ход которой ждёт выделения сервером внепиковых вычислительных ресурсов. Использует бесплатную внепиковую квоту подписки Coding Plan, не расходуя обычную квоту плана.
Смысл сессии, хода и приёмки сохраняется; сервер определяет только время запуска.
_Не использовать_: внепиковая задача (кроме одноимённой функции ZCode App), внепиковая сессия (у сессий нет типа; внепиковость — свойство отправки), off-peak task

**Талон (ticket)**:
Подтверждение места в серверной очереди для внепиковой отправки. Одна отправка может последовательно использовать несколько талонов. Получение талона ставит отправку в очередь; после его готовности нужно запуститься за несколько минут, затем действует максимальная продолжительность выполнения.
После использования талон необходимо закрыть расчётом.
_Не использовать_: билет, элемент очереди, запись очереди

**Отправка Start Plan (start-plan send)**:
Отправка, которая направляет запросы модели этого хода через квоту подписки Start Plan. Запускается сразу, как обычная отправка: без талона, ожидания и расчёта.
Смысл сессии, хода и приёмки сохраняется.
_Не использовать_: задача Start Plan, сессия Start Plan (у сессий нет типа; start plan — свойство отправки)

**Рабочее дерево (worktree)**:
Рабочее дерево git, в котором работает исполнитель, изолированное от основного дерева. Его создаёт Claude; проект только сохраняет сведения о нём.

### Согласование действий

**Запрос разрешения (permission request)**:
Запрос исполнителя о допустимости операции перед её выполнением.
_Не использовать_: окно разрешений, permission prompt

**Вопрос (question)**:
Вопрос от исполнителя, требующий ответа, а не разрешения или отказа.
_Не использовать_: пользовательский ввод, user input

**Шлюз согласования (gate)**:
Весь процесс обработки запроса разрешения: жёсткие правила → проверка моделью → ожидание ответа.
_Не использовать_: согласователь, фильтр

**Жёсткое правило (hard rule)**:
Правило, которое никто не может отменить. Совпадение сразу передаёт запрос человеку, минуя проверку моделью.
_Не использовать_: чёрный список

**Контур управления (control plane)**:
Части каталога данных инструмента, которые исполнитель не должен трогать: ожидающие запросы и ответы, реестр, конфигурация, события, снимки заданий. Это каталог данных за вычетом стандартного корня рабочих деревьев `worktrees/` и рабочего дерева текущей сессии.
Операция, направленная туда, или вызов CLI инструмента активирует жёсткое правило самозащиты.
_Не использовать_: каталог состояния, внутренний каталог

**Проверка моделью (model review)**:
Модели поэтапно оценивают запрос разрешения: разрешить его или передать человеку. Возможны предварительная проверка, быстрая проверка и углублённая проверка; итог — только разрешение или передача человеку, никогда отказ.
_Не использовать_: вердикт, judge, автоматическое согласование

**Предварительная проверка (pre-screen)**:
Необязательная оценка Jev перед исходной быстрой проверкой. Достаточные свидетельства и положительный результат дают раннее разрешение; остальные результаты передаются исходной быстрой проверке, которую этот этап не заменяет.
_Не использовать_: замена быстрой проверки, shadow

**Локальный пропуск (local skip)**:
До отправки известно, что свидетельств недостаточно или надёжное удаление секретных данных невозможно. Запрос к Jev не выполняется, запускается исходная быстрая проверка; это не вывод модели о наличии риска.
_Не использовать_: flag, отказ модели

**Быстрая проверка (fast screen)**:
Первый этап исходной проверки моделью ZCode: можно ли сразу разрешить действие. Отрицательный или неразбираемый результат передаётся углублённой проверке; ошибка вызова — человеку.
_Не использовать_: предварительная проверка Jev, shadow, предварительное согласование

**Углублённая проверка (slow review)**:
Повторная оценка после отрицательного или неразбираемого результата быстрой проверки ZCode. Может разрешить действие или передать его человеку, никогда не отказывает напрямую.
_Не использовать_: вторая инстанция, окончательный вердикт

**Ожидание ответа (pending)**:
Запрос разрешения или вопрос ждёт ответа человека, ход приостановлен на этом месте. Во внешнем представлении обозначается blocked.
_Не использовать_: блокировка, ожидание согласования, зависание

**Квитанция (receipt)**:
Событие `executor.approve` / `deny` / `answer`, записанное в `events.jsonl` после того, как runner обработал ответ.
Именно оно указано в `eventType` результата `approve` / `deny` / `answer` с `--json`; если не найдено — null.
_Не использовать_: ack, сообщение подтверждения

### Модели

**Уровень модели (model tier)**:
Группа моделей ZCode по возможностям и стоимости. Передача работы, быстрая и углублённая проверки ZCode выбирают уровень, а не конкретное имя модели; Jev использует фиксированную версию вне этой таблицы уровней.
_Не использовать_: имя модели, номер модели

**Уровень размышления (thought level)**:
Глубина рассуждений исполнителя за один ход; задаётся при создании сессии.
_Не использовать_: effort, reasoning, ступень размышления

**Персональный файл конфигурации провайдера (personal provider config file)**:
JSON с единственным провайдером, который мы записываем для дочернего процесса app-server. Содержание получается из выбранного провайдера
(источник — `~/.zcode/v2/config.json` либо платформенный ключ, расшифрованный из файла учётных данных для провайдера аккаунта, D19). Путь передаётся через `ZCODE_PERSONAL_PROVIDER_CONFIG_FILE` (decisions D14).
_Не использовать_: таблица провайдеров, registry

**Встроенный файл конфигурации провайдеров (builtin provider config file)**:
Файл `zcode-builtin.json` из поставки ZCode App. Путь передаётся дочернему процессу через `ZCODE_BUILTIN_PROVIDER_CONFIG_FILE`.
Проект только вычисляет и передаёт путь, не создаёт и не изменяет содержимое файла.

**Провайдер аккаунта (account provider)**:
Запись coding plan с префиксом `account:` во встроенном файле провайдеров: личная или командная подписка. После входа пользователя в App через аккаунт (OAuth)
ключ не записывается в config.json: App получает его за пользователя и сохраняет в файле учётных данных. Проект расшифровывает ключ и использует как обычный платформенный ключ через персональный файл D14
(decisions D19).
_Не использовать_: OAuth provider, zhipu-account

**Файл учётных данных (credentials file)**:
`~/.zcode/v2/credentials.json` — плоский JSON, в котором ZCode App хранит данные входа; значения преимущественно зашифрованы с префиксом `enc:v1:` (AES-256-GCM).
Проект только читает файл и расшифровывает четыре ключа (active provider, user_info, два api-key coding plan), а для внепиковой отправки дополнительно `zcodejwttoken` (D20). Остальные ключи не читает и не расшифровывает.
_Не использовать_: хранилище ключей, keychain

### Наблюдение

**Репозиторий (repo)**:
Корень основного репозитория, соответствующего рабочему дереву сессии; определяется через общий каталог данных git, а не по имени каталога. Пуст, если рабочее дерево удалено или не удалось определить путь.
Отличается от `repoRoot` реестра: тот фиксирует исходный репозиторий при `new` и существует только при cwd в рабочем дереве. Репозиторий имеет значение и тогда, когда cwd — сам основной репозиторий.
_Не использовать_: имя проекта, рабочая область
