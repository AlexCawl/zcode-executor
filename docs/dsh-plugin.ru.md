# dsh-plugin/ — плагин на стороне DSH

[English](dsh-plugin.md) · [中文](dsh-plugin.zh-CN.md) · Русский

Часть для DSH (DeepSeek Harness) подключает CLI этого репозитория к DSH: инструкции по передаче работы (SKILL.md + объявление в системном промпте)
+ панель наблюдения «zcode 任务» («задачи zcode») в официальной правой боковой панели. Обновляется примерно раз в секунду, не расходует квоту, предназначена только для просмотра.

**Определение плагина находится в корне репозитория**: поле `dsh` корневого `package.json` + корневой `cordis.patch.yml` (id строки `zcode-executor`).
Пакет npm `zcode-executor` сам является плагином DSH: установка по имени пакета на странице плагинов настольного приложения автоматически регистрирует bundle.
Не нужны ни `link:`, ни ручное редактирование конфигурации профиля. Корневой список `files` включает в npm tarball `cordis.patch.yml` и
`dsh-plugin/lib` (результат сборки); все peer-зависимости необязательны, поэтому глобальная установка CLI по-прежнему не требует зависимостей
(окружение выполнения на стороне DSH предоставляет хост). `test/dsh-manifest.test.mjs` защищает это определение от расхождений.

`dsh-plugin/` содержит только **исходники и результат сборки** (TypeScript + отдельный пакет pnpm). Каталог включён 2026-10-11 через `git subtree`
из отдельного репозитория (Gitea `kyomio/dsh-zcode-executor`) с сохранением всей истории; старый репозиторий заморожен.
**Единственная связь с CLI** — построчный протокол NDJSON команды `zcode-executor watch --json`.

## Обзор каталогов

| Путь | Содержимое |
| --- | --- |
| `dsh-plugin/src/` | Исходники TypeScript: index (точка входа плагина cordis), routes (маршруты потока NDJSON), watch-process, bridge (мост плагина zen-remote), skill-link (символическая ссылка в `~/.dsh/skills`), client/ (панель React) |
| `dsh-plugin/lib/` | Результат сборки (tsc + встроенная упаковка через `build-client.mjs`), **хранится в git** и публикуется с пакетом npm |
| `dsh-plugin/skills/zcode-executor/` | Единственная **символическая ссылка** SKILL.md на корневой `skills/zcode-executor/SKILL.md` (единый источник истины; npm пропускает символические ссылки при упаковке, поэтому skill-link во время выполнения использует корневой skills/ как запасной вариант; поддерживаются обе структуры) |
| `dsh-plugin/test/` | 112 тестов, все на заглушках; сессии DSH не создаются, токены не расходуются |
| `dsh-plugin/SPEC.md` / `README.md` | Полная спецификация, включая решения по тестированию и границы / установка и архитектура |
| Корневой `cordis.patch.yml` | Патч регистрации bundle (**определён в корне, а не в dsh-plugin/**) |

## Разработка и тестирование

```sh
cd dsh-plugin
pnpm install        # peer/dev-зависимости
npm run build       # tsc с двумя tsconfig + build-client.mjs; результат lib/ хранится в git
npm run verify      # только проверка типов
node --test test    # 112 тестов (не входят в корневой npm test: плагину нужны зависимости pnpm; корневые тесты остаются без зависимостей)
```

После изменения кода плагина нужно перезапустить настольное приложение DSH; `npm run preview` запускает локальный предпросмотр панели на макетных данных.

## Выпуск

Отдельного номера версии нет: плагин следует за основным пакетом — `npm version` + tag → публикация npm через `publish.yml`; код входит в tarball.
После изменения плагина нужно выполнить `npm run build` (lib хранится в git); `test/dsh-manifest.test.mjs` проверяет наличие результатов сборки.

## Синхронизация с upstream

Старый репозиторий заморожен. Если изменения плагина появились в другом месте, их можно получить через subtree:

```sh
git subtree pull --prefix=dsh-plugin <旧仓库路径或 remote> main
```

`<旧仓库路径或 remote>` — исходный заполнитель для пути или remote старого репозитория.
